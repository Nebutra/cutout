# Converge prototype quality and throughput

## Goal

Make the desktop prototype pipeline truthful, deterministic under concurrent UI
interaction, and materially faster while supporting every image route that has
real generation/edit capability and keeping high-fidelity recommendations
separate from executable support.

## Confirmed Facts

- Many image models can edit images. Provider brand or model rank must not be a
  hard allowlist when an exact model route has verified capability and an
  executable adapter.
- OpenAI-style providers use the reviewed OpenAI image endpoint adapter. That
  predicate describes one transport, not the global set of image-edit-capable
  models.
- High-fidelity page quality is a recommendation tier informed by product
  benchmarks; it must never be represented as the definition of image-edit
  capability.
- Resource QA warnings were made observational so one model rejection cannot
  strand an otherwise complete resource pack. Reintroducing a blocking quality
  issue would regress complete delivery.
- Integrity failures remain non-waivable and must block resource publication.
- Complete suite generation currently shares React projections, the global
  Asset Production revision, and slice state. Parallel suite execution is not
  safe until those authorities are isolated.

## Requirements

### R1. Image route support and fidelity recommendation

- One shared route-capability owner must combine exact model capability evidence
  with an implemented Provider adapter. Model name heuristics or leaderboard
  rank alone are insufficient.
- Any route with proven `image-generation` may be used for generation. Any route
  with proven `image-edit` and an executable adapter may consume visual
  references through `edit-image`, regardless of Provider brand.
- Unsupported transport fails before a paid call with `capability-required`;
  it must not be advertised and then fail inside the Provider service.
- The OpenAI image endpoint predicate remains the authority only for the
  OpenAI `/images/generations` and `/images/edits` adapter. Other Providers need
  their real request/response adapter and tests, not inclusion in that predicate.
- Automatic AI setup must choose an executable image route. It should prefer a
  high-fidelity-recommended route when available, but may configure another
  supported route and clearly describe the quality trade-off.
- Prototype UI must distinguish `recommended for high fidelity`, `supported`,
  and `adapter required`; only the last state blocks execution.
- Recommendation metadata must not mutate the exact model id sent to the
  Provider or override authenticated catalog evidence.

### R2. Truthful quality evidence

- Every newly generated page must persist a review record bound to the exact
  page bytes, reviewer route, verdict, failures, and review time.
- Every resource-pack binding must retain the production task's QA verdict and
  relevant observational warnings, bound to its content-addressed artifact.
- Delivery evidence must aggregate actual page and resource reviews as
  `passed` or `attention-required`; the existing unconditional
  `qualityReviewStatus: recorded` claim must be removed.
- Review rejection or unavailability remains non-blocking when artifact
  integrity passes, but it must be visible and must never be represented as a
  pass.
- Historical artifacts without review evidence remain recoverable and
  selectable, but cannot produce new terminal quality proof until reviewed or
  regenerated.

### R3. Stable human selection

- A human suite selection made while sibling suites are still generating must
  survive every later orchestration publish and terminal auto-selection step.
- Agent auto-selection is allowed only when no valid human selection exists.
- Selection restoration must continue to verify page media and resource-pack
  authority before projecting the suite.
- After a human selection exists, sibling progress must not overwrite the
  singular plan/Design System/pages projection, and later production commits
  must not leave the selected resource-pack authority pointing at a sibling.

### R4. Partial Design System availability

- Once candidate execution settles with at least one ready Design System, the
  user may select a ready direction even if a sibling failed.
- Failed candidates remain visible and retryable; ready candidates and their
  bytes must not be regenerated by that retry.
- Zero ready candidates remains a blocking failure.

### R5. Safe throughput convergence

- Independent direct-asset and board-production work may interleave, but all
  image-producing work must share the existing global ceiling of three.
- The implementation must not parallelize complete suites against the current
  shared Asset Production/slice authority.
- Page order, stable anchor conditioning, selected-first suite scheduling,
  retry frontiers, resource attribution, and exact planned/actual image-call
  accounting must remain unchanged.
- No fixed page, route, candidate, or material quantity may be introduced.

## Acceptance Criteria

- [ ] Route-capability tests prove model-level `image-generation` and
      `image-edit` evidence is intersected with an implemented adapter; provider
      kind or model name alone cannot authorize a paid call.
- [ ] OpenAI-style, Google/Gemini, and any implemented Qwen route advertise and
      execute only their real capabilities; unimplemented routes return
      `capability-required` before charging.
- [ ] Rendered preflight coverage proves a supported non-recommended model can
      run while an adapter-missing route fails before the first paid call.
- [ ] Automatic setup prefers a high-fidelity-recommended supported route but
      falls back to another executable image route without calling it
      unsupported.
- [ ] Recommendation tests prove quality tier changes never change support,
      Provider protocol, exact model transport id, or approval behavior.
- [ ] Page review records survive workspace persistence/recovery and bind to the
      exact page digest.
- [ ] Delivery evidence fails closed when new review records are missing or
      stale, and reports `attention-required` for rejected/unavailable page or
      resource QA instead of claiming a pass.
- [ ] A rendered concurrency regression selects the first ready suite while a
      sibling is still generating and proves the human selection remains final.
- [ ] A rendered partial-candidate regression proves ready Design Systems are
      selectable while a failed sibling remains retryable.
- [ ] Throughput tests prove direct and board work overlap while total image
      concurrency never exceeds three.
- [ ] Retry tests prove ready pages, resources, and candidate siblings are not
      replayed.
- [ ] `pnpm agent:validate`, focused Vitest, full lint/type-check/build, and
      `git diff --check` pass.

## Out Of Scope

- Claiming support for an image-edit route without an implemented and tested
  request/response adapter.
- Treating leaderboard rank as API capability or authenticated execution
  evidence.
- Parallel complete-suite execution before per-suite production and slice state
  have isolated authorities.
- Automatic paid QA rerolls or silently regenerating rejected work.
- Fixed commercial candidate, route, page, or material counts.
