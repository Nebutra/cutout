# Multi-action sprite family

## Goal

Turn any supported natural-language subject request and identity reference into an
independently reviewable family of actions, directions and detached effects,
then deliver an accepted multi-animation runtime-neutral bundle.

## Background

- The parent task has a real Qwen-backed atomic action runner, deterministic v5
  cutout, targeted role repair, native semantic acceptance and atlas compiler.
- `game-asset.plan.v1` intentionally represents one atomic action closure. It
  must remain compatible with retained signed evidence.
- Agent Sprite Forge's strongest reusable practice is to generate coherent
  action groups independently, derive scale from an accepted master action,
  split body and wide FX, and assemble engine layouts only after action QA.

## Product Decisions

- This is the first implementation child after the parent atomic Game foundation.
- Multi-frame actions default to one coherent action-sheet Provider call followed
  by deterministic splitting. Selected failed cells use isolated-frame repair.
- Complete Game replacement includes asset and managed engine outcomes; gameplay
  code and project integration remain under the Coding Profile.

## Requirements

### R1. Intent-authored family plan

- Infer useful actions, directions, frame counts, body/FX separation and timing
  from the requested playable outcome. Users may edit the proposal but need not
  select raw grids or processor flags.
- Compile the family into independent atomic `game-asset.plan.v1` action groups
  sharing one exact identity reference and art-direction revision.
- Keep grounded body, airborne body, projectile, impact and detached FX in
  explicit compatibility classes with declared dependencies.
- Choose an explicit action source strategy. Default multi-frame actions to one
  coherent multi-row sheet generation, retain that exact source, and split cells
  deterministically. Preserve the current isolated-frame strategy for single
  assets, high-risk actions and targeted repair.

### R2. Master scale and anchor profile

- Derive one content-addressed scale/anchor profile from an accepted grounded
  idle or run clip, never from requested values or an unaccepted candidate.
- Reuse the exact profile revision across compatible grounded clips. Reject
  unexplained scale/anchor drift rather than compensating per action.
- Airborne actions and FX use their own anchor policies without weakening the
  grounded profile.

### R3. Independent production and repair

- Preview, execute, review and accept each action group through the existing
  native authority boundary.
- A repair may call the Provider only for selected failed roles/groups and must
  preserve every accepted sibling byte, receipt, revision and hash.
- When one cell in a coherent sheet fails, repair it as an isolated frame and
  merge it through explicit source/derivation lineage; do not regenerate the
  accepted sheet siblings or silently re-slice a changed source.
- Family status derives from exact child closure; caller-authored completion or
  quality scores cannot admit an action.

### R4. Runtime-neutral family delivery

- Bind accepted clips, frame order, observed timing, anchors, scale profile,
  body/FX origins and atlas cells in versioned family contracts.
- Compile one or more deterministic atlases from accepted clips only. Preserve
  loop versus one-shot semantics.
- Preview the actual compiled atlas/timing consumer and export through the managed
  bundle path without engine-specific assumptions.

### R5. Workbench projection

- Show identity/master state, action progress, blockers, repair scope, stale
  dependencies, compiled playback and delivery in the existing Game workbench.
- Natural-language intent launches this projection directly; no scenario card or
  mandatory Profile selector is added.

### R6. Real-only evidence

- Fixtures may validate schema and rejection paths only. Family real-host and
  accepted-delivery states require retained native evidence for every child clip
  and exact family semantic acceptance.

### R7. Cross-identity generality

- Treat the retained reference and requested outcome as the identity/action
  authority. Do not bake the first rehearsal's human proportions, red outfit,
  blade, feet anchor, action list or alpha envelope into family compilation.
- Infer a bounded action program from the request and subject kind. A player,
  NPC, quadruped creature and grounded prop may receive different body actions,
  anchors, timing and optional detached effects without exposing raw processor
  or grid selection to the user.
- Prompt bodies in topology-neutral language. Weapon-, anatomy-, projectile- and
  effect-specific constraints appear only when the request supplies that cue.
- Keep historical retained family plans replayable after the authoring compiler
  becomes generic. A new compiler result receives a new content identity; old
  signed evidence is never reinterpreted.

## Acceptance Criteria

- [ ] One character intent deterministically proposes idle, run, attack-body and
      detached attack-FX groups with exact dependency and timing contracts.
- [ ] The initial four-group rehearsal uses no more than one Provider generation
      call per coherent action group; additional calls are attributable only to
      selected failed-cell repair.
- [ ] Deterministic grid splitting derives observed rows/cells from decoded source
      bytes, binds each cell to the shared source receipt/hash, and blocks dimension
      or containment mismatch instead of copying requested grid facts.
- [ ] An accepted idle/run clip derives one stable profile; compatible body clips
      reference its exact revision and incompatible airborne/FX clips do not.
- [ ] Repairing one failed action/role leaves accepted sibling bytes, receipts,
      revisions and hashes unchanged.
- [ ] A malformed, partial, stale-profile or semantically unaccepted child blocks
      family acceptance and neutral delivery.
- [ ] One retained real Qwen family closes native verification and semantic review
      for every required group, then compiles an accepted multi-animation bundle.
- [ ] Runtime playback consumes atlas cells and manifest timing, and managed export
      receipts match every persisted content identity.
- [ ] Existing atomic Game plans and retained signed rehearsals remain replayable.
- [x] At least two visually and topologically distinct retained references compile
      through the same public authoring/native request path without a hard-coded
      Courier, humanoid, blade, feet-anchor or fixed four-group assumption.
- [x] A non-humanoid/prop contract test proves intent-derived actions and prompts;
      one second real Qwen rehearsal proves the generalized path beyond fixtures.

## Out Of Scope

- Map production, engine-specific files, gameplay controllers and video ingestion.
- Procedurally invented placeholder art or fixture-backed production claims.
