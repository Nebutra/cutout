# Agent Sprite Forge coverage ledger

## Goal

Make replacement status an evidence-backed conjunction over every declared Agent
Sprite Forge user outcome instead of a manually asserted roadmap percentage.

## Background

- Upstream `main` is pinned at
  `64fd0b57d3f2ae117ef0a95e4c2decc25b4c9dd2` for the initial ledger.
- Cutout already distinguishes contract, real Host and rehearsal evidence in its
  Design OS benchmark. Game outcome coverage must not invent a parallel readiness
  authority or let quality scores authorize Host maturity.
- Current atomic Sprite production has real Qwen evidence and a candidate neutral
  bundle, but lacks exact semantic acceptance for that retained run.

## Requirements

### R1. Stable outcome inventory

- Inventory upstream outcomes at the user-result level: static/animated sprite,
  directional locomotion, multi-action family, body/FX separation, projectile/
  impact, scale profile, prop/terrain extraction, preview animation, neutral atlas,
  six map modes, structured collision/zones, layered preview, Godot handoff, Unity
  handoff and video-to-sprite.
- Record the upstream repository/commit and local contract owner for every entry.
- Project-specific gameplay assembly is recorded as Coding Profile integration,
  not as Game Asset Profile ownership.

### R2. Evidence-derived maturity

- Each entry is exactly one of `unsupported`, `contract`, `real-host`, or
  `accepted-delivery` and cites the owning verifier plus exact evidence identities.
- Fixtures/schema tests may justify only `contract`. Retained real Host receipts
  and bytes are required for `real-host`. Exact semantic acceptance and verified
  delivery are required for `accepted-delivery`.
- Caller-authored status, benchmark score, documentation, screenshots or an
  assistant review cannot advance an entry.

### R3. Replacement theorem

- `replacementComplete` is derived only when every required pinned outcome reaches
  `accepted-delivery` and every evidence reference re-verifies.
- Missing, stale, downgraded or newly required upstream outcomes make the result
  incomplete. There is no weighted average or quality-score override.
- Upstream changes produce a reviewable inventory diff; they do not silently alter
  the pinned release claim.

### R4. Product projection

- Expose a compact internal inspection view showing covered, blocked and unavailable
  outcomes with evidence links. Do not add a scenario picker or marketing dashboard.
- Public claims/docs may consume only a signed/verified ledger projection.

## Acceptance Criteria

- [ ] The initial pinned inventory covers every declared Sprite, Map, engine and
      video outcome without duplicates or implementation-specific Python flags.
- [ ] Fixture-only evidence cannot advance any entry beyond `contract`.
- [ ] Missing semantic acceptance keeps the current real Qwen atlas below
      `accepted-delivery` even when generation and byte verification pass.
- [ ] Tampered/stale receipts, bytes, bundle hashes or verifier fingerprints
      downgrade/block the owning entry and replacement result.
- [ ] Replacement is false unless every required entry is `accepted-delivery`.
- [ ] A changed upstream commit produces an explicit added/removed/changed outcome
      review before a new replacement claim is issued.
- [ ] Game quality score and Design OS evidence maturity remain independently
      visible and cannot authorize ledger entries for each other.

## Out Of Scope

- Competitive marketing copy, weighted feature scoring and using GitHub README
  screenshots as production evidence.
