# Design - publish and reinstall Cutout 0.1.5

## Release Source Boundary

The dirty local `main` worktree remains untouched. A temporary sibling worktree
is created from `github/main` on a dedicated release branch. The reviewed
conversation persistence product commit is cherry-picked there, then release
metadata is updated in that isolated worktree. Task records stay outside the
product release commit.

The release branch reaches `github/main` through a pull request because the
repository ruleset requires a PR and the aggregate `Quality gate` status. The
tag is created only from the reviewed merge commit after the version validator
passes against `0.1.5`.

## Version Contract

All version-bearing surfaces changed by the previous `v0.1.4` release commit
are advanced to `0.1.5`. Generated Codex plugin runtime data is regenerated by
the repository-owned build command rather than edited independently. The
changelog describes both immutable Agent conversation branches and the latest
release hardening included from `github/main`.

The Agent capability package version and Codex plugin version remain aligned
with the desktop package. Protocol identifiers remain unchanged because this is
a package release, not a protocol revision.

## Publication Gates

Publication is fail-closed in this order:

1. `v0.1.5` and its Release must not already exist.
2. Source version files and tag must match.
3. The tag commit must be reachable from `github/main`.
4. Apple, updater, and Windows signing secret names must all exist in the
   protected `release` environment.
5. The repository quality gate and all four native build jobs must pass.
6. The final single-authority publish job must collect every platform, validate
   signatures/metadata, attest assets, create a draft, upload the complete set,
   and only then publish it.

If any gate fails before the tag exists, stop without tagging. If CI fails after
an immutable tag is pushed, do not move or reuse that tag; diagnose and prepare
a new patch version.

## Installation Flow

After public release verification, download `SHA256SUMS` and the
`macos-aarch64` DMG to a temporary directory. Verify the checksum before
mounting. Verify the app and DMG with `codesign`, `spctl`, and `stapler`.

Quit Cutout, inventory all installed bundles, and move the old
`/Applications/Cutout.app` to a unique path in `~/.Trash`. Copy the verified app
from the mounted DMG into `/Applications`, eject the DMG, refresh
LaunchServices/Spotlight, and launch only the installed bundle.

The final check reads `Info.plist`, validates the signature and notarization,
confirms the running executable path, and inspects the visible desktop window.

## Rollback

Before publication, delete only the temporary release branch/worktree if the
candidate is rejected; do not touch the user's dirty worktree. After local
installation, rollback consists of quitting Cutout, moving the new bundle to a
new Trash path, and restoring the timestamped old bundle. Published tags and
Releases are never rolled back by mutation.
