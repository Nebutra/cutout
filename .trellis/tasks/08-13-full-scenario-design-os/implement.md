# Full-scenario Design OS - program plan

## Stage 0: Freeze Meaning And Current Truth

- [ ] Preserve the completed Kernel contracts and prototype compatibility corpus.
- [ ] Record current coupling baselines: closed material kinds, workspace domain
      imports, scenario branches, Profile registrations and truthful Host limits.
- [ ] Freeze the first Scene Extension Law and an allowlisted extension-surface
      audit before adding another production Profile.
- [ ] Freeze generic required-role closure, observed-artifact evidence and
      identity-fidelity fixtures extracted from the Commerce rehearsal without
      importing Commerce role names into the Kernel.

Exit: the product can distinguish Kernel, Platform, Profile, Workbench and Host
ownership, and no planned capability is presented as shipped.

## Stage 1: Design Profile Platform

- [ ] Complete `08-13-design-profile-platform`: manifest/closure, universal brief,
      graph compilation, bindings, install/disable/upgrade and conformance kit.
- [ ] Adapt Commerce to the manifest/closure without changing its semantics or
      benchmark evidence.
- [ ] Add a synthetic held-out Profile that compiles and renders through generic
      fallbacks without Kernel or navigation changes.
- [ ] Add promotion-packet and cross-Host canonical parity fixtures; prove an
      unsupported Host preserves the blocked Outcome instead of rewriting it.

Exit: Profile admission and removal are deterministic, reversible and enforced.

## Stage 2: One General Workbench

- [ ] Continue `08-12-design-os-desktop-workbench` after Platform contracts freeze.
- [ ] Split the monolithic prototype workspace behind a domain-neutral controller
      and renderer/inspector/action registries.
- [ ] Route direct manipulation and Agent edits through Project ChangeSets.
- [ ] Preserve legacy prototype behavior until mixed-Outcome parity tests pass.

Exit: UI and Commerce use the same shell and semantic command path; unsupported
schemas remain visible and safe.

## Stage 3: Third-Scenario Proof

- [ ] Complete the runtime-neutral sprite vertical slice in
      `08-13-sprite-production-workflow` through the Profile Platform.
- [ ] Add layered maps and managed neutral bundle delivery after sprite family
      graph/QA/repair behavior passes.
- [ ] Run the extension audit and prove the Game Asset Profile required no Kernel,
      global navigation, approval or history branches.
- [ ] Prove one failed frame/action repairs locally while accepted siblings retain
      hashes, and one shared identity-lock revision creates an exact ImpactSet.

Exit: UI, Commerce and Game Asset pass one lifecycle and a shared-lock ImpactSet
fixture while retaining domain-specific IR and evaluation.

## Stage 4: Time, Targets And Project Evolution

- [ ] Complete Temporal IR/Host Gate B and register Timeline presentation/actions.
- [ ] Complete Project Change Management, portable Project Bundle and Library
      release/update closures required for long-lived mixed Projects.
- [ ] Add target adapters only over accepted neutral artifacts, starting with the
      targets demanded by proven workflows rather than an engine/channel matrix.

Exit: mixed spatial, interactive, textual and temporal Outcomes can evolve and
deliver through one Project history.

## Stage 5: Production Evidence And Expansion

- [ ] Extend the Profile-neutral Design OS benchmark to UI, Game Asset and
      Temporal without changing prior metric meaning.
- [ ] Add separate frozen Profile Outcome scorecards and a matrix projection that
      cannot convert quality points into evidence maturity or release readiness.
- [ ] Require contract -> conformance -> real Host -> rehearsal evidence per
      Profile and block releases on critical regressions.
- [ ] Admit brand/marketing/packaging and later spatial/physical/3D Profiles only
      from real user workflows and the same extension gate.

Exit: "full-scenario" describes an open extension architecture with several
production-proven Profiles, not an unsupported completeness claim.

## Cross-Program Validation

- [ ] Trace F1-F14 to child fixtures and durable benchmark evidence.
- [ ] Run Kernel, Profile, ChangeSet, Workbench, Host, persistence/recovery,
      delivery and cross-profile impact suites.
- [ ] Run type-check, lint, builds, relevant Rust checks and
      `rtk git diff --check` for each implementation slice.
- [ ] Read `cutout.agent-capabilities.json` before every Agent-surface change;
      synchronize CLI/MCP/protocol/manifest/docs/generated runtime and run
      `pnpm agent:validate` only when the implementation is real.

## Rollback Points

- Profile Platform wraps existing Commerce/Kernel behavior before becoming the
  only installation path.
- Workbench registries sit behind prototype adapters before legacy branches are
  retired.
- Game Asset is removable and cannot migrate existing prototype snapshots.
- Target adapters cannot mutate accepted neutral artifacts or broaden paths.
